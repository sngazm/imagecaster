## Worker のデプロイ

Worker（`imagecaster-api`）は手元から `wrangler` で出します。GitHub Actions は使いません。

```bash
pnpm test            # 先にテストを通す
pnpm deploy:worker
```

環境変数は Cloudflare Dashboard（Workers & Pages → `imagecaster-api` → Settings → Variables and Secrets）で
管理します。`wrangler.toml` に `keep_vars = true` があるので、デプロイしても Dashboard の値は消えません。
変数を足すときも Dashboard か `wrangler secret put` で入れます。

<Aside type="caution">
以前は GitHub Actions（`deploy-worker.yml`）で Worker を出し、環境変数も GitHub の Secrets から
`wrangler secret bulk` で流し込む作りでした。GitHub 側に値が揃っておらず、動かせば本番の値を空で
上書きする状態だったため、2026-10-19 に workflow ごと削除しました。
Cloudflare の GitHub 連携（Workers Builds）も環境変数が消える不具合
（[Issue #8871](https://github.com/cloudflare/workers-sdk/issues/8871)）があるので、Worker には
つながず、手元から出します。
</Aside>

## 管理画面・公開サイトのデプロイ

管理画面（`imagecaster-admin`）と公開サイト（`imagecaster-web`）は Cloudflare Pages の Git 連携で
出ます。`main` に push すると Pages がビルドして配信するので、手で出す手順はありません。

ドキュメントサイトは GitHub Actions（`deploy-docs.yml`）で GitHub Pages に出ます。

## Web サイト自動デプロイの設定

エピソードの公開・更新・削除時に自動で Web サイトをリビルドするには、Cloudflare Pages のデプロイフックを設定します。

1. Cloudflare Dashboard → Workers & Pages → Web サイトのプロジェクト
2. **Settings** → **Builds & deployments** → **Deploy hooks** → **Add deploy hook**
3. 名前（例: `podcast-worker`）とブランチ（通常は `main`）を入力
4. 表示された URL をコピー

```bash
npx wrangler secret put WEB_DEPLOY_HOOK_URL
# プロンプトで URL を入力
```

## ビルド状況表示の設定

管理画面でビルドの進捗を確認するには Cloudflare API Token が必要です。

1. [Cloudflare API Tokens](https://dash.cloudflare.com/profile/api-tokens) → **Create Token**
2. Permissions: `Account > Cloudflare Pages > Read`
3. トークンをコピー

```bash
npx wrangler secret put CLOUDFLARE_API_TOKEN
npx wrangler secret put PAGES_PROJECT_NAME   # 例: podcast-web
```
