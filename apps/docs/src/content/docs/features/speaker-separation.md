話者ごとにトラックが分かれた音声があれば、区間ごとの音量を比べて「誰が喋っているか」を
判定できます。機械学習による diarization と違い、トラックが分かれている限り確実に判定できます。

判定した話者は VTT の `<v 話者名>` タグとして保存され、公開サイトでは話者名が色付きで
表示されます。

## 必要なもの

DAW からトラック別に書き出した音声を zip にまとめたもの。ファイル名の末尾に
`Track 1`、`Track 2` のようにトラック番号が入っていれば、そのまま渡せます。

**本編の音声とトラックのタイムラインが一致していることが前提です。** 編集で頭出しや
カットが入ってずれていると判定結果が丸ごと無意味になります。文字起こしワーカーは尺の
乖離を検出すると警告を出します。

## 使い方

1. 管理画面の **設定 → 文字起こし** で、トラック番号への話者名の割り当てを登録する
2. エピソードの編集画面で話者トラックの zip をアップロードする
3. 文字起こしが実行されると、話者付きの文字起こしが生成される

ゲスト回などトラック構成が変わる場合は、エピソードごとに割り当てを上書きできます。

### 非発話トラック

BGM や効果音のトラックは、話者名を空欄にして非発話として登録します。除外しないと
**全員が黙っている区間が BGM トラックに誤判定されます**。割り当てを登録しなかった
トラックも判定に使われません。

## 判定の仕組み

1. 各トラックを 16kHz モノラルにデコードし、0.2 秒ごとのフレームに区切って音量を測る
2. マイクのゲイン差で判定が偏らないよう、トラックごとの音量を揃える
3. 単語ごとに、その区間で最も大きく鳴っているトラックをフレームの多数決で決める
4. 話者が切り替わった位置でセグメントを分け直す

Whisper のセグメント境界は音響的な切れ目であって話者の切れ目ではないため、
「A さんの発言 + B さんの相槌」が 1 セグメントに同居します。単語単位の時刻を使って
切り直すことでこれを解消しています。

判定を安定させるために、次の調整が入っています。

- 音量が小さいまま話者が入れ替わる判定は採らない（息継ぎの合間に拾う物音を無視する）
- 単語 1 つきりの短いブロックは隣の発話に吸収する（相手が喋り続けている最中の相槌は、
  書き起こされるテキストが相手のものになるため）

## 同時発話

2 人が同時に同じ言葉を言う区間（番組冒頭で声を揃えて番組名を言う、など）は
`あずま・鉄塔` のように連結した話者名になります。公開サイトでは両者の名前が
縦に並んで表示されます。

**既定では検出しません。** 本編の会話中まで検出を効かせると、相槌のかぶりや同時に
笑った箇所を拾ってしまい、誤検出のほうが圧倒的に多くなるためです。実測では、
検出範囲を設けずに 50 分のエピソードを処理したところ 38 件が同時発話と判定され、
そのうち本物は冒頭の 1 件だけでした。

使う場合は **設定 → 文字起こし** で「冒頭で 2 人が声を揃える箇所がある」を有効にし、
検出範囲（冒頭からの秒数）を指定します。範囲の外では検出しません。

範囲の中でも、相槌のかぶりと区別するために次の条件を満たす必要があります。

- 区間の半分以上のフレームで両者が同程度の音量で鳴っている
- 声が重なっているフレームが 3 つ以上ある（立ち上がりが重なっただけの一瞬を除く）
- 区間の長さが 0.3 秒以上ある

## 後処理

話者の判定と同時に、文字起こしには次の後処理がかかります。設定は
**設定 → 文字起こし** で変更できます。

### セグメントの統合

同じ話者の連続したセグメントをまとめます。Whisper は音響的な切れ目で区切るため、
同じ人の続きの発話がいくつにも割れてしまうためです。

### 誤字の置き換え

文字起こしがよく取り違える固有名詞を辞書で直します。一般的な語を対象にすると
意図しない箇所まで置き換わるので、前後を含めた形にしておくと安全です。

### やり直し

これらの後処理は Whisper の生出力（`transcript.raw.json`）を入力にしているため、
**文字起こしをやり直さずに何度でも適用し直せます**。

- エピソード単位: 編集画面の「後処理だけやり直す」
- 公開済み全体: 設定 → 文字起こしの「公開済みエピソードに再適用」

一括の再適用は Worker のリソース制限を避けるため、Cron が少しずつ処理します。

## 既存エピソードに話者を付ける

**話者は後処理では付きません。** 音量の比較には音声そのものが要るため、判定は
文字起こしワーカー側でしか行えません。すでに文字起こし済みのエピソードに話者を
付けるには、トラックを用意したうえで音声から取り直す必要があります。

1. エピソードの編集画面で話者トラックの zip をアップロードする
2. 「音声から文字起こしをやり直す」を実行する
3. ワーカーが拾って処理し、話者付きの文字起こしに置き換わる

現在の文字起こしは新しい結果で置き換わります。処理中のエピソードは横取りしません。

## LLM による校正

辞書は「この表記をこう直す」と決め打ちできるものしか扱えません。文脈を読まないと
判断できない誤り（同音異義語の取り違えなど）は Claude に直させます。

本文を丸ごと書き換えさせると、毎回結果が変わって検証できないうえ、フィラーを消したり
口語を書き言葉に整えたりと、頼んでいない改変が混ざります。そこで
**「どのセグメントをどう直すか」の一覧だけを出させ、適用はこちらで行います**。

提案は機械的に検査してから適用します。

- 元のテキストが実際のセグメントと一致するか
- 文字数が大きく変わっていないか（0.6〜1.6 倍の範囲外は捨てる）
- 空にならないか

弾いた提案も結果に含まれるので、何が却下されたか確認できます。

`ANTHROPIC_API_KEY` を Worker の secret に設定すると使えます。

## Claude の感想

文字起こしを読んだ Claude の感想を、エピソードページに掲載できます。番組の紹介でも
要約でもなく、一人の聞き手としての反応です。

文字起こしが完了すると自動で生成されます（`ANTHROPIC_API_KEY` がある場合）。
管理画面から書き直しと削除ができます。
