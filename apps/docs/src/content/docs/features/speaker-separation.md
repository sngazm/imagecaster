話者ごとにトラックが分かれた音声があれば、区間ごとの音量を比べて「誰が喋っているか」を
判定できます。機械学習による diarization と違い、トラックが分かれている限り確実に判定できます。

判定した話者は VTT の `<v 話者名>` タグとして保存され、公開サイトでは話者名が色付きで
表示されます。

## 必要なもの

DAW からトラック別に書き出した音声を zip にまとめたもの。ファイル名の末尾に
`Track 1`、`Track 2` のようにトラック番号が入っていれば、そのまま渡せます。

**本編の音声とトラックのタイムラインが一致していることが前提です。** 編集で頭出しや
カットが入ってずれていると判定結果が丸ごと無意味になります。文字起こしワーカーは尺の
乖離を検出すると警告を出します。

## 使い方

1. 管理画面の **設定 → 文字起こし** で、トラック番号への話者名の割り当てを登録する
2. エピソードの編集画面で話者トラックの zip をアップロードする
3. 文字起こしが実行されると、話者付きの文字起こしが生成される

ゲスト回などトラック構成が変わる場合は、エピソードごとに割り当てを上書きできます。

### 非発話トラック

BGM や効果音のトラックは、話者名を空欄にして非発話として登録します。除外しないと
**全員が黙っている区間が BGM トラックに誤判定されます**。割り当てを登録しなかった
トラックも判定に使われません。

## 判定の仕組み

1. 各トラックを 16kHz モノラルにデコードし、0.2 秒ごとのフレームに区切って音量を測る
2. マイクのゲイン差で判定が偏らないよう、トラックごとの音量を揃える
3. 単語ごとに、その区間で最も大きく鳴っているトラックをフレームの多数決で決める
4. 話者が切り替わった位置でセグメントを分け直す

Whisper のセグメント境界は音響的な切れ目であって話者の切れ目ではないため、
「A さんの発言 + B さんの相槌」が 1 セグメントに同居します。単語単位の時刻を使って
切り直すことでこれを解消しています。

判定を安定させるために、次の調整が入っています。

- 音量が小さいまま話者が入れ替わる判定は採らない（息継ぎの合間に拾う物音を無視する）
- 単語 1 つきりの短いブロックは隣の発話に吸収する（相手が喋り続けている最中の相槌は、
  書き起こされるテキストが相手のものになるため）

## 同時発話

2 人が同時に同じ言葉を言う区間（番組冒頭で声を揃えて番組名を言う、など）は
`あずま・鉄塔` のように連結した話者名になります。公開サイトでは両者の名前が
縦に並んで表示されます。

**既定では検出しません。** 本編の会話中まで検出を効かせると、相槌のかぶりや同時に
笑った箇所を拾ってしまい、誤検出のほうが圧倒的に多くなるためです。実測では、
検出範囲を設けずに 50 分のエピソードを処理したところ 38 件が同時発話と判定され、
そのうち本物は冒頭の 1 件だけでした。

使う場合は **設定 → 文字起こし** で「冒頭で 2 人が声を揃える箇所がある」を有効にし、
検出範囲（冒頭からの秒数）を指定します。範囲の外では検出しません。

範囲の中でも、相槌のかぶりと区別するために次の条件を満たす必要があります。

- 区間の半分以上のフレームで両者が同程度の音量で鳴っている
- 声が重なっているフレームが 3 つ以上ある（立ち上がりが重なっただけの一瞬を除く）
- 区間の長さが 0.3 秒以上ある

## 後処理

話者の判定と同時に、文字起こしには次の後処理がかかります。設定は
**設定 → 文字起こし** で変更できます。

### セグメントの統合

同じ話者の連続したセグメントをまとめます。Whisper は音響的な切れ目で区切るため、
同じ人の続きの発話がいくつにも割れてしまうためです。

### 相槌の整理

実際に言っていても、文字で読むと相槌が並ぶだけになる箇所を整理します。2 段階あります。

**繰り返しを抑える** — 「うんうんうんうんうんうん」を既定で 3 回で止めます。

**相槌だけの行を消す** — 「はい。」「なるほど。」のように、それだけで 1 行に
なっているものを丸ごと落とします。公開済み 6 本で数えたところ、全セグメントの
2〜17% がこれに該当しました。

消さないものが 2 つあります。

| 残すもの | 理由 |
|---|---|
| 読点で終わる行（「なんか、」「でも、」） | 相槌ではなく**次の発話の一部**。消すと文が壊れる |
| 問いかけの直後の行（「汚い手?」→「はい。」） | 相槌ではなく**返事**。消すと問いが宙に浮く |

読点で終わる行は無視できない量があります。14 文字以下のセグメント 5312 件のうち
2252 件が読点終わりで、最多は「なんか、」の 206 件でした。ここを対象に含めると
文章が壊れます。

対象の語は **設定 → 文字起こし → 相槌** で編集できます。完全一致する行のほか、
**対象の語の並びだけで出来た行**も落ちます。「ふんふんふん。」「ははは。」のような
語形を1つずつ登録していくときりがないためです。区切りは詰めてから判定するので、
「はい、はい、はい。」「はっはっはっ。」も対象になります。

「バチバチバチバチ」「どんどんどんどん」は擬音や副詞で意味を持つため残ります。
「はい、それでいいと思います。」のように相槌を含むだけの文も残ります。

判定は**統合したあと**にもう一度行います。「そう」と「そうそう」が統合されて
「そうそうそう」が生まれることがあり、読者が見る最終形で判断しないと取り逃がします。

問いかけの直後でも、同じ語を2回以上繰り返したものは落とします。返事としては
1回で足り、繰り返しは相槌の勢いでしかないためです（「逆に?」→「そうそうそう」）。

### 誤字の置き換え

文字起こしがよく取り違える固有名詞を辞書で直します。一般的な語を対象にすると
意図しない箇所まで置き換わるので、前後を含めた形にしておくと安全です。

### やり直し

これらの後処理は Whisper の生出力（`transcript.raw.json`）を入力にしているため、
**文字起こしをやり直さずに何度でも適用し直せます**。

- エピソード単位: 編集画面の「後処理だけやり直す」
- 公開済み全体: 設定 → 文字起こしの「公開済みエピソードに再適用」

一括の再適用は Worker のリソース制限を避けるため、Cron が少しずつ処理します。

## 既存エピソードに話者を付ける

**話者は後処理では付きません。** 音量の比較には音声そのものが要るため、判定は
文字起こしワーカー側でしか行えません。すでに文字起こし済みのエピソードに話者を
付けるには、トラックを用意したうえで音声から取り直す必要があります。

1. エピソードの編集画面で話者トラックの zip をアップロードする
2. 「音声から文字起こしをやり直す」を実行する
3. ワーカーが拾って処理し、話者付きの文字起こしに置き換わる

現在の文字起こしは新しい結果で置き換わります。処理中のエピソードは横取りしません。

## 落とされた発話の拾い直し

Whisper は 1 文を丸ごと落とすことがあります。音は入っていて、聞けば喋っているのに
出力に現れません。**文字起こしだけを見ても気づけない**ので、音量と突き合わせて
見つけます。

1. 音声全体のフレームごとの音量を測る（0.2 秒刻み、95 パーセンタイルで正規化）
2. 文字起こしの無い区間のうち、半分以上が発話で埋まっているものを拾う
3. その区間だけを切り出して認識し直す
4. 時刻をずらして元の結果に挟む

全体をやり直すより速く、他の箇所の結果を壊しません。話者を切り直す前に行うので、
拾い直した分にも話者が付きます。

拾わないものが 2 つあります。**0.6 秒未満の空白**は息継ぎや文の切れ目で普通に空くので
無視します。**区間の半分以上が発話でないもの**も拾いません。端に物音があるだけの区間を
拾うと、意味の無い断片が増えます。

1 エピソードで拾い直す上限は 30 箇所です（`recovery.max_gaps`）。全部やると
文字起こしそのものより時間がかかります。長いものから順に処理します。

## LLM による校正

辞書は「この表記をこう直す」と決め打ちできるものしか扱えません。文脈を読まないと
判断できない誤りは Claude に直させます。技術系の話題でカタカナのままになっている
製品名（「アサナ」→ Asana、「クロードコード」→ Claude Code）や、同音異義語の
取り違え（「コンテクスト帳」→「コンテクスト長」）が対象です。

**API キーは要りません。** 文字起こしを回すマシンの `claude` コマンドを呼びます。
文字起こしが完了すると自動で走ります。

### 本文を書き換えさせない

本文を丸ごと書き換えさせると、毎回結果が変わって検証できないうえ、フィラーを消したり
口語を書き言葉に整えたりと、頼んでいない改変が混ざります。そこで
**「どの行をどう直すか」の一覧だけを出させ、適用はこちらで行います**。

提案は機械的に検査してから当てます。

- 元のテキストが実際の行と一致するか
- 文字数が大きく変わっていないか（0.6〜1.6 倍の範囲外は捨てる）
- 空にならないか

### 置換規則にして辞書に還元する

当てた修正は、行ごとの差し替えではなく**置換規則**に変換して保存します。こうすると
後処理をやり直しても修正が残り、番組全体に効くものは次回以降の文字起こしにも
自動で効きます。指摘された誤りを毎回直さずに済みます。

規則を作るときの決まりごとがあります。

| 決まり | 理由 |
|---|---|
| 1 行に 2 箇所の修正があれば分ける | まとめると「オーパス5で、100万トークンのコンテクスト帳」のような、その行にしか当たらない規則になる |
| 差分が短ければ直前の同じ文字種まで遡る | 「帳」→「長」を登録すると、あらゆる「帳」が置き換わる。「コンテクスト帳」→「コンテクスト長」なら安全 |
| ひらがなへは遡らない | 助詞や活用語尾を含めても意味がない（「その帳」のような規則になる） |
| 削除は規則にしない | 前後の文脈しだいで壊れやすい |

規則には行き先が 2 つあります。

| 種類 | 行き先 | 効きはじめ |
|---|---|---|
| その回かぎりの文脈に依るもの | そのエピソード | すぐ |
| 番組全体に効きそうなもの | **提案** | 人が承認したら |

**辞書には自動で入りません。** 設定 → 文字起こし に提案が並ぶので、目を通して
「辞書に入れる」か「見送る」かを選びます。

### なぜ自動で入れないのか

辞書は公開済みの全エピソードに効くので、機械の判断で足すと文章を壊すからです。
実際に壊しました。

| 入った規則 | 何が起きたか |
|---|---|
| `メール → mail` | 「メールフォーム」が「mailフォーム」に |
| `コード → Code` | 「コードを書く」が「Codeを書く」に |
| `スクリーン → のスキーム` | 文中に「のスキーム」が湧いた |
| `短期 → 短気` | 「短期的には」まで置き換わる |
| `テスト → 鉄塔` | 言うまでもない |

歯止めを足すたびに別の抜け道が見つかりました。**2 文の差分は語彙規則ではない**ので、
1 事例から一般的な知識を導こうとする限り誤爆は止まりません。承認を挟むほうが確実です。

その回かぎりの修正は承認を待ちません。そのエピソードの中でしか当たらないので、
壊れる範囲がその回に閉じているためです。

## Claude の感想

文字起こしを読んだ Claude の感想を、エピソードページに掲載できます。番組の紹介でも
要約でもなく、一人の聞き手としての反応です。これも API キーは要らず、文字起こしを
回すマシンの `claude` コマンドを呼びます。

文字起こしが完了すると自動で生成されます。管理画面から書き直しと削除ができます。

長さは 240〜360 文字に収めます。「300 文字程度」とだけ伝えると 434 文字が返って
きたので、範囲を数字で示し、外れたら実際の文字数を伝えて詰め直させています。
2 回試して収まらなければ、長さより感想があることを優先してそのまま採ります。

## 音声認識そのものの設定

後処理を厚くする前に、入力の質を確かめる価値があります。

文字起こしワーカーは `config.yaml` の `whisper.prompt_file` を読んで、Whisper に
`initial_prompt` として渡します。ここに番組名と出演者名を書いておくと固有名詞の認識精度が
上がり、**句読点付きの文を書いておくと出力にも句読点が付きます**（Whisper はプロンプトの
書き方を引き継ぐため）。

実測では、プロンプトを渡すだけで 25 分の回の「句読点を含む行」が 3 行から 785 行になり、
「暑がり」が「厚刈り」になるような誤認識も直りました。辞書で後から直していた分の
かなりの部分は、ここで起きなくなります。

```
この音声はポッドキャスト番組「Image Cast」です。話しているのは「あずま」と
「鉄塔(てっとう)」です。技術、デザイン、表現などについての雑談です。
```
