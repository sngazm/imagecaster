# 切り抜き動画 仕様

管理画面で、AI が選んだ切り抜きを**動画にする前に**音声と字幕で確かめ、その場で直し、
OK を出す。OK を出したものだけが縦・横・正方形の 3 本に描かれ、予定日に投稿される。

生成側の道具は別リポジトリ（[imagecaster-video](https://github.com/sngazm/imagecaster-video)）。
そちらの `SPEC.md` に、なぜその形なのかが書いてある。

## 何ができればよいか

1. 動画を描く前に、音声と字幕だけで仕上がりを確かめられる
2. 字幕の文字・改行・出す／出さないを、その場で直せる
3. カット位置（始まりと終わり）を、その場で動かせる
4. 縦・横・正方形のどれで描いても、プレビューで見た字幕とずれない
5. OK を出すと 3 本が描かれ、予定日に X・Bluesky・YouTube Shorts・Instagram へ出る

スマホから触れることを前提に組む。

## 誰が何をするか

**描画はクラウドではできない。** ffmpeg も素材も手元（Mac / WSL）にある。一方、
確かめて直すのに描画は要らない。音声は R2 にあり、字幕は文字と時刻の並びでしかない。
だから**確かめて直すところまでを管理画面で済ませ、手元には決まったものを描かせるだけ**にする。

```
手元（Mac / WSL）                 管理画面（Cloudflare）
  区間を選び、下書きを作る
  （字幕の区切り・文字時刻・画像）
        ↓ R2 に置く  ──→   音声＋字幕でプレビュー
                             文字・改行・カット位置を直す
                             OK ＋ 投稿日時
        ↓ watch.py が見つける ←──
  下書きのとおりに 3 本描く
        ↓ R2 に上げる  ──→   Cron が予定日に投稿する
```

R2 を共有の置き場にするのは、既存の音声・書き起こしと同じ考え方。手元から見て
公開 URL で読め、Worker から書ける。新しい経路を増やさない。

手元でしか作れないのは、字幕の区切り（LLM）と文字ごとの時刻（`align.py`）。
管理画面はこれを作らない。渡されたものを並べ替え、書き換えるだけ。

## R2 の置き場

```
episodes/{storageKey}/clips/
├── index.json                  この回の切り抜き一覧
└── {clipId}/
    ├── meta.json               状態・版の一覧・投稿の予定と結果
    ├── draft.json              下書き。プレビューと編集の対象
    ├── v1/
    │   ├── portrait.mp4        1080x1920
    │   ├── landscape.mp4       1920x1080
    │   ├── square.mp4          1080x1080
    │   ├── draft.json          描いたときの下書きの控え
    │   └── manifest.json       画像の出どころ
    └── v2/ …
```

版は上書きしない。OK を取り消して直し、描き直すと v2 になる。投稿済みの動画が
どの下書きから描かれたかを後から追えるようにするため。

### draft.json

```json
{
  "revision": 4,
  "source": { "start": 629.0, "end": 727.0 },
  "cut": { "start": 644.0, "end": 712.0 },
  "subs": [
    {
      "id": "s12",
      "speaker": "あずま",
      "start": 651.32,
      "end": 653.9,
      "of": "切層もない",
      "chars": [651.32, 651.5, 651.71, 651.9, 652.1],
      "rows": ["節操もない"],
      "skip": false
    }
  ],
  "cards": [{ "at": 660.2, "word": "…", "image": "…" }]
}
```

- **時刻はすべてエピソードの音声上の秒。** プレビューはエピソードの `audio.mp3` を
  そのまま鳴らす。切り抜きの頭からの秒にすると、カット位置を動かすたびに全部の字幕が
  ずれる
- `source` は下書きが字幕を持っている範囲。`cut` の前後に**余白 15 秒**を付けて作る。
  カット位置は `source` の中でしか動かせない。それより外へ広げたいときは、手元で
  下書きから作り直す（区切りと文字時刻が無い範囲は、管理画面では作れない）
- `of` は元の書き起こしの文字、`chars` はその 1 字ごとの読み始め。**管理画面は
  この 2 つを書き換えない。** 直すのは `rows`（画面に出す文字と改行）と `skip` だけ
- `rows` を連ねたものが `of` と違えば、それは文字を直したということ。読み上げの
  進み（白くなっていく位置）は、`of` の進みを `rows` の字数に比例で写す
- `skip: true` は字幕を出さない。音は残る
- 枚を割る・繋ぐ：割るときは `of` と `chars` を同じ位置で切る。繋ぐときは連ねる。
  どちらも `of` を連ねた全体は変わらない
- 元の書き起こしに無い字幕を足すときは `of: ""`、`chars: []` とし、`start` / `end` を
  前後の隙間に置く
- `revision` は保存のたびに 1 増える。保存は「いま見ている revision」を添えて送り、
  食い違えば弾く（スマホと PC で同時に開いたときに、黙って上書きしない）

### meta.json

```json
{
  "id": "c1",
  "episodeId": "285",
  "label": "脳が5つにちぎれる",
  "status": "approved",
  "approvedRevision": 4,
  "latest": 1,
  "versions": [
    { "n": 1, "createdAt": "…", "revision": 4, "layouts": ["portrait", "landscape", "square"] }
  ],
  "publishAt": "2026-09-27T12:00:00Z",
  "postText": "…",
  "posts": {
    "bluesky": { "enabled": true, "layout": "square", "postedAt": null, "url": null, "error": null },
    "x": { "enabled": true, "layout": "landscape", "postedAt": null, "url": null, "error": null },
    "youtube": { "enabled": true, "layout": "portrait", "postedAt": null, "url": null, "error": null },
    "instagram": { "enabled": true, "layout": "portrait", "postedAt": null, "url": null, "error": null }
  }
}
```

`status`:

| 値 | 意味 |
|---|---|
| `draft` | 下書き。管理画面で直せる |
| `approved` | OK が出た。描画待ち。下書きは直せない |
| `rendered` | `approvedRevision` の 3 本が揃った。投稿待ち |
| `published` | 投稿が済んだ（一部が失敗していても、出せるものは出した） |
| `rejected` | ボツ |

`approved` と `rendered` は OK を取り消せば `draft` に戻る。`published` は戻らない。

## 字幕の置き方

**字の位置を描画エンジンに決めさせない。** 行をまるごと渡して描かせると、ブラウザは
約物の連続を勝手に詰め、行の幅を整数に丸め、その挙動がブラウザごとに違う。Pillow とも
合わない。プレビューと動画で字幕を一致させるには、どちらも同じ表から同じ式で座標を出し、
1 字ずつそこへ置く。

- フォントは Noto Sans JP（可変）の wght 700。管理画面も同じファイルを読む
- 送り幅はフォントの表（1em = 1000）から引く。表は生成側が `clip metrics` で書き出し、
  管理画面に同梱する（`apps/admin/src/lib/clip-metrics.json`）。カーニングと約物詰めは掛けない
- 行は書記素（結合文字・異体字セレクタを含めた 1 字）に分け、送り幅を足して x を出す。
  行は中央に寄せる。ベースラインは行の上端から 1.16em
- 表に無い字（絵文字など）は 1em として置き、管理画面で警告する。環境によって
  別のフォントで描かれ、見た目が揃わない
- 読み終えた字は白、これからの字は薄く。薄いほうは**不透明な色で決める**。半透明の
  合成は Pillow と canvas で規則が違う

### 改行は 3 レイアウトで共通

1 行の上限を **em（字数）で決める**。レイアウトごとに変えるのは字の大きさと位置だけ。
プレビューで 1 回確かめれば、3 本とも同じ改行で出る。横型は幅が余っても短い行の
2 段になるが、確かめる手間が 3 倍になるよりよい。

| | 縦 | 横 | 正方形 |
|---|---|---|---|
| 大きさ | 1080x1920 | 1920x1080 | 1080x1080 |
| 1 行の上限 | 15em | 15em | 15em |
| 字の大きさ | 68px | 80px | 64px |

字の大きさ・字幕の高さ・人物や画像カードの位置は、生成側の `config.py` が持ち、
`clip-metrics.json` に一緒に書き出す。管理画面はそれを読んでガイド線を引く。数値を
二箇所に書かない。

### 揃っていることの確かめ方

```bash
# imagecaster-video で
uv run --with playwright python scripts/glyph-parity.py
```

管理画面の `clipGlyphs.ts` をそのまま Chromium で動かし、生成側の `Renderer` が描いた
ものと重ねて、1 字ごとの位置のずれを測る。約物の連続・欧文・半角カナ・異体字セレクタ・
結合文字・上限いっぱいの行などを 3 レイアウトで見る。`clip-metrics.json` が古くなって
いないかも見る。**字幕の描き方か `config.py` を変えたら、これを通すこと。**

残る差は縁のアンチエイリアスと、Pillow が字の x を整数に丸めること（±0.5px）だけ。

### ガイド線

プレビューは 3 レイアウトを切り替えて見られる。枠の中に次を線で出す。

- 字幕の 1 行の上限（これを越えた行は赤くなり、OK を出せない）
- 人物と画像カードが占める場所
- 投稿先の UI がかぶる場所（Shorts / Reels の右下と下端）

## API

既存の `/api/episodes/:id/...` に揃える。

| Method | Path | 何をするか |
|---|---|---|
| GET | `/api/episodes/:id/clips` | 一覧 |
| GET | `/api/episodes/:id/clips/:clipId` | meta.json |
| PUT | `/api/episodes/:id/clips/:clipId` | 生成側が下書きを置く／描いた版を登録する |
| GET | `/api/episodes/:id/clips/:clipId/draft` | 下書き |
| PUT | `/api/episodes/:id/clips/:clipId/draft` | 下書きを保存する（revision を添える） |
| PUT | `/api/episodes/:id/clips/:clipId/status` | OK（投稿日時・本文・投稿先つき）／取り消し／ボツ |
| POST | `/api/episodes/:id/clips/:clipId/upload-url` | 動画を置く先を渡す（レイアウトごと） |
| GET | `/api/clips/pending` | 描画待ち（`approved`）の切り抜き。手元が拾う |

動画そのものは R2 の公開 URL から直接読む。音声と同じ扱いで、Worker を通さない。
**上げるほうも通さない。** 数十 MB を Worker に流す理由がないので、Presigned URL を
渡して手元から直に R2 へ入れさせる。

生成側は「動画を 3 本置く → 版として登録する」の順で呼ぶ。逆にすると、登録は済んで
いるのに動画が無い版が画面に出る。

下書きの保存では Worker が検算する。`of` を連ねたものが保存前と変わっていないこと、
`chars` の数が `of` の字数と合うこと、`cut` が `source` の中にあること。合わなければ弾く。

`/api/clips/pending` と投稿の Cron は**全走査しない**。全エピソードの meta.json を読む
作りだと Worker のリソース制限（Error 1102）に達する。`index.json` に
`"エピソードID/切り抜きID"` の索引を 2 本持つ。

| 索引 | 入るとき | 出るとき |
|---|---|---|
| `clipRenderIds` | OK が出た | 版が登録された／OK が取り消された |
| `clipPostIds` | 版が登録された | 全部の投稿先が済んだ／OK が取り消された |

## 画面

`/episodes/:id/clips/:clipId`。スマホでは縦に積む。

```
┌─────────────────────────┐
│ ← #285 脳が5つにちぎれる         │
├─────────────────────────┤
│  [縦] [横] [正方形]             │   レイアウトの切り替え
│  ┌───────┐                │
│  │ ガイド線  │                │   canvas。字幕は動画と同じ座標で描く
│  │  字幕    │                │
│  └───────┘                │
├─────────────────────────┤
│ ◀▓▓░░▓▓▓░▓▓░░▓▓▓▓░░▓▓▶  │   帯＝字幕 1 枚。両端のつまみ＝カット位置
├─────────────────────────┤
│ 0:02 え、ちなみに           [⋯] │   押すとその時刻へ。文字はその場で直せる
│ 0:04 基本的にコマンド。     [⋯] │   ⋯ ＝ 割る・前と繋ぐ・出さない・ここに足す
│ ⋮                             │
├─────────────────────────┤
│ 投稿 9/27 21:00  [本文] [投稿先] │
│                  [ボツ] [OK]    │
└─────────────────────────┘
```

- 音は `<audio>` でエピソードの音声を鳴らし、`cut` の終わりで止める
- 字幕の文字は枚の中で直す。改行がそのまま `rows` の区切りになる
- カット位置のつまみは字幕の切れ目に吸い付く。枚の途中では切らない
- 直したものは自動で保存する。OK を出せるのは、保存が済んでいて、上限を越えた行と
  表に無い字の警告が無いときだけ
- 描画が済んだら同じ画面で 3 本を再生できる

## 描画

1. 手元の `watch.py` が `/api/clips/pending` を見て拾う
2. `draft.json` を読み、`cut` の範囲を縦・横・正方形で描く。**区切りも文字も決め直さない。**
   LLM は呼ばない
3. 3 本を R2 に上げ、版として登録する

生成側は、`of` を連ねたものが元の書き起こしと**一字一句一致すること**を確かめてから描く。
合わなければ止める。字幕と音がずれるのを防ぐための関門で、下書きを管理画面で直せるように
なっても緩めない。管理画面が `of` を書き換えないのはこのため。

**文字を直して直るのはその動画の字幕だけ**で、公開サイトの文字起こしは誤字のまま。
誤認識は文字起こし側の失敗なので、目立つものは辞書に回す。ここでやるのは応急処置。

## 投稿

Cron（5 分おき）が `clipPostIds` を見て、`status` が `rendered` で `publishAt` を
過ぎたものを投稿する。投稿先ごとに結果を `meta.posts` に残し、失敗した先だけ次の回で
やり直す。1 つの失敗で他の投稿先を止めない。

| 投稿先 | 既定のレイアウト |
|---|---|
| X | 横 |
| Bluesky | 正方形 |
| YouTube Shorts | 縦 |
| Instagram（Reels） | 縦 |

認証の持ち方と各 API の制約は、実装するときに公式の文書で確かめてここに書き足す。
