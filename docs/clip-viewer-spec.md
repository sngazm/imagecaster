# 切り抜き動画ビューワー 仕様

管理画面で、AI が作った切り抜き動画を確認し、字幕の直しを指示し、作り直させる。

生成側の道具は別リポジトリ（[imagecaster-video](https://github.com/sngazm/imagecaster-video)）。
そちらの `SPEC.md` に、なぜその形なのかが書いてある。

## 何ができればよいか

1. 動画が再生できる
2. 字幕を 1 枚ずつ見て、直しを指示できる
3. シークバーの上に字幕の区間が並び、追加・削除も指示できる
4. 指示を反映した作り直しが走り、v2・v3 と見比べられる

将来はここから投稿予約まで繋げる。スマホから触れることを前提に組む。

## 誰が何をするか

**描画はクラウドではできない。** ffmpeg も素材も手元（WSL）にある。だから
管理画面は**指示を預かるだけ**で、実際の作り直しは手元の道具が引き取る。

```
管理画面（Cloudflare）        手元（Mac / WSL）
  動画を見る
  直しを指示  ──→ R2 に置く
                        ↓  watch.py が見つける
                   Claude Code が読んで作り直す
                        ↓
                   v2 を R2 に上げる  ──→ 管理画面で見比べる
```

R2 を共有の置き場にするのは、既存の音声・書き起こしと同じ考え方。手元から見て
公開 URL で読め、Worker から書ける。新しい経路を増やさない。

## R2 の置き場

```
episodes/{storageKey}/clips/
├── index.json                  この回の切り抜き一覧
└── {clipId}/
    ├── meta.json               区間・版の一覧・状態・未処理の指示
    ├── v1/
    │   ├── clip.mp4
    │   ├── subs.json           その版で使った字幕の区切り
    │   ├── cards.json          その版で出した画像
    │   └── manifest.json       画像の出どころ
    └── v2/ …
```

版は上書きしない。作り直しても前の版は残る。見比べたいのと、悪くなったときに
戻れるようにするため。

### meta.json

```json
{
  "id": "c1",
  "episodeId": "285",
  "label": "脳が5つにちぎれる",
  "range": ["10:49", "11:47"],
  "clip": { "start": 644.0, "duration": 68.0 },
  "latest": 2,
  "status": "draft",
  "versions": [
    { "n": 1, "createdAt": "…", "note": "初回" },
    { "n": 2, "createdAt": "…", "note": "字幕の指示を反映", "fromRequest": "r1" }
  ],
  "requests": [
    { "id": "r1", "createdAt": "…", "appliedIn": 2, "items": [ … ] }
  ]
}
```

`status` は `draft` / `approved` / `rejected`。OK を出したものだけが、あとで
投稿予約に進む。

### 指示（requests[].items）

**直接書き換えるのではなく、指示として預かる。** 字幕は音のタイムスタンプに
紐づいているので、文字だけ差し替えると音とずれる。作り直す側が、指示を読んで
区切りを決め直す。

```json
{ "type": "edit",   "index": 5, "text": "こう直してほしい" }
{ "type": "note",   "index": 5, "text": "区切りを前に寄せて" }
{ "type": "delete", "index": 7 }
{ "type": "insert", "afterIndex": 7, "text": "ここに入れたい" }
```

`index` はその版の字幕の通し番号。版が変わると番号もずれるので、指示は
**どの版に対するものか**を持つ（`requests[].baseVersion`）。

## API

Worker に足す。既存の `/api/episodes/:id/...` に揃える。

| Method | Path | 何をするか |
|---|---|---|
| GET | `/api/episodes/:id/clips` | 一覧 |
| GET | `/api/episodes/:id/clips/:clipId` | meta.json |
| PUT | `/api/episodes/:id/clips/:clipId` | 生成側が版を追加するとき |
| GET | `/api/episodes/:id/clips/:clipId/versions/:n/subs` | その版の字幕 |
| POST | `/api/episodes/:id/clips/:clipId/requests` | 直しの指示を預かる |
| PUT | `/api/episodes/:id/clips/:clipId/status` | OK / ボツ |
| GET | `/api/clips/pending` | 未処理の指示がある切り抜き（手元が拾う） |

動画そのものは R2 の公開 URL から直接読む。音声と同じ扱いで、Worker を通さない。

## 画面

`/episodes/:id/clips/:clipId` を新しく作る。エピソード詳細に埋め込むと、
シークバーと字幕一覧を並べる場所が足りない。スマホで縦に積めるようにもしたい。

```
┌─────────────────────────┐
│  ← #285 脳が5つにちぎれる    v2 ▾ │   版を切り替える
├─────────────────────────┤
│                         │
│        動画                │
│                         │
├─────────────────────────┤
│ ▓▓░░▓▓▓░▓▓░░▓▓▓▓░░▓▓    │   シークバー＋字幕の区間
├─────────────────────────┤
│ 0:02 え、ちなみに…      [直す] │
│ 0:04 基本的にコマンド。  [直す] │   字幕一覧。押すとその時刻へ飛ぶ
│ ⋮                        │
├─────────────────────────┤
│ 指示 3 件   [作り直す] [OK] │
└─────────────────────────┘
```

- シークバーの帯は字幕 1 枚に対応。再生位置に合わせて色が変わる
- 帯を押すとその字幕へ、字幕を押すとその時刻へ
- 「直す」で、その 1 枚に対する指示を書く
- 帯と帯の間を押すと「ここに追加」
- 指示は溜めておいて、まとめて「作り直す」で送る

## 作り直しの流れ

1. 管理画面が指示を `POST .../requests` で預ける
2. 手元の `watch.py` が `/api/clips/pending` を見て拾う
3. Claude Code が開き、指示と元の書き起こしを読んで `subs.json` を決め直す
4. `clip make --subs-file` で描く
5. v2 として R2 に上げ、`meta.json` に版を足す
6. 管理画面で v1 と v2 を切り替えて見比べる

**指示をそのまま字幕にしない。** 「区切りを前に寄せて」のような書き方が来るし、
文字を直したら音とのずれも直さないといけない。読んで判断するのは Claude Code の
仕事で、道具は渡されたものを描いて検算するだけ、という切り分けは生成側と同じ。
