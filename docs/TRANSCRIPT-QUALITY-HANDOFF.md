## 決めたこと: 優先順位

公開サイトの文字起こしを読み返して、引っかかる箇所を 4 つに分けた。**1 と 2 を先にやる。**
3 と 4 はその後の品質の話で、1・2 が片付かないと校正の品質にも響く。

1. **相槌・合いの手の扱い。** 相手の短い相槌が話し手の行に吸われる／逆に相槌の音量が
   話し手の単語を奪う。何かしらの工夫が要る（後述）。
2. **話者分離の切れ目。** 文を正しい場所で分割できておらず、序盤からありえない場所で
   切れている。読み心地への悪影響が大きく、校正の品質にも響く。**当面の目標は
   「話者分離を完璧にやる」**。→ 2026-09-06 に節単位の判定へ置き換えた（下記）。
3. 長い行の句読点の密度（後回し）。
4. 校正の取りこぼし（後回し）。

## 問題 1: 相槌・合いの手

### 現象（C11 の公開データ）

- 31:14 藤原「…次も作ろうって気持ちになるっていうか**なるほどなるほど。**」← 末尾はあずま
- 30:37 藤原「がなんか苦笑いして終わりみたいなこともあります。**あー、そうなんだ。**」
- 34:48 あずま「ザ・メイキングを夜見たがるより**え、なんですか?**ザ・メイキングって…」← 藤原の問い
- 76:15 あずま「ありがとうございました。さようなら。**さようなら。**」

逆向きもある。相槌の音量が一瞬上回った単語だけが相槌の主に振られ、話し手の文が
語の途中で割れる（「いろい｜ろこうリ｜ハビリ」）。

### 分かっている原因

- **話者分離は単語ごとの音量の argmax**（`speaker.py _label_words`）。相槌が被った単語は
  相槌の主に取られる。それを抑える「弱い切替の抑制」（音量 0.25 未満なら直前の話者を保つ）と、
  2026-09-06 に足した「節の中で多数派 7 割に揃える」（`_smooth_within_clauses`）が、
  今度は本物の相槌を話し手に吸わせる。除外条件が「本人だけが鳴っている（`is_unmistakable`）」
  なので、話し手が喋り終わる直前に被せた相槌は残らない。
- **ミックス側の Whisper が相槌を書くかは運任せ**。書かれると話し手の行に埋まり、Worker の
  `removeEmbeddedBackchannels` が一部を落とすだけ。
- **トラック補完は相槌だけの候補を足さない**（`track_recovery.py` の `NOISE`）。相槌の本文は
  ミックスの書き方に依存している。

### 候補（未着手）

a. **相槌はそもそも書かない方針に統一する。** ミックスの本文から相槌を落とす（Worker の
   standalone/embedded 削除を強化）。問いへの返事「はい」は残す既存ルールとの整合が要る。
b. **トラック別の音量で相槌区間を検出し、話者分離の判定から除外する。** 相手が喋っている最中の
   短い突出（0.6 秒未満）は相槌とみなし、単語の話者判定に使わない。相槌が単語を奪う側の問題に効く。
c. **節揃えの除外条件を緩める。** 少数派の区間で少数派の音量が十分にあり、本文が相槌・短い問いの
   形なら、多数派に揃えず独立させる。吸われる側の問題に効く。
d. 音イベント分類器（YAMNet、laughter-detection）で笑い声を事前に除く。別枝。

### 測り方

- 正解データの話者一致（`scripts/transcript-eval/score_any.py`、厳密と重なり許容）。
- 公開行の末尾・行中に相手の相槌が埋まった数（`audit-site.mjs` に検査を足すか、
  Worker の `removeEmbeddedBackchannels` が落とした数を出す）。
- 最終判定は読む（`read-back.mjs` と、人が 30〜35 分あたりを通読）。

## 問題 2: 話者分離の切れ目（2026-09-06 に着手、節単位の判定に置き換え済み）

### 現象（C11 の公開データ）

- 33:07 藤原「それがすごい、天才…」／あずま「じゃんみたいな。」← 「天才じゃん」は一人の発話。
- 30:32 藤原「できたつって…」／あずま「夫…」／藤原「がなんか苦笑いして」← 「夫」は藤原の語。
- 3:03 あずま「そんな中で、藤原さんが本を出しました。」／あずま「出」／藤原「しました。」

### 分かった原因

- 単語単位の argmax なので、交代の判定が語の途中に落ちる。節揃え（多数派 7 割）は折衷で、
  Whisper のセグメント境界の中しか見ない。「夫」は Whisper が誰も鳴っていない 0.9 秒に置いた
  単語で、単独のセグメントだったので節揃えの対象外だった。
- **Whisper は発言の最初の語の開始時刻を、前の発言の終わりまで伸ばす。** 「出」183.78〜184.12
  の 183.78 は前の人の「した。」の終わり。0.2 秒刻みの音量では、その 1 文字が前の人の
  「明白な」発言に見える。旧 `_frame_range` の切り捨て・切り上げが偶然これを打ち消していたので、
  四捨五入に直すだけだと正解率が落ちる（切り分けで確認）。
- 「音量が小さい交代は直前の話者を保つ」規則が、小声の藤原の「え、なんですか?」をあずまに渡していた。

### やったこと（transcriber `speaker.py`）

`split_by_speaker` を「節を最小単位に決める」に置き換えた（`_split_words` → `_clauses` →
`_decide_clause` → `_decide_plain`）。

- 節は句読点か 0.3 秒以上の間で切り、Whisper のセグメント境界はまたぐ。
- 単語を「同じ人・同じ競り具合（本人以外も鳴っているか）」で run にまとめ、競っておらず 0.3 秒・
  2 文字以上で本人だけが鳴っている run を錨（明白）とする。
- 多数派 7 割以上なら多数派の節。錨になる少数派（相槌）だけ独立。競っている少数派は、隣に同じ人の
  錨があればそこへ、無ければ多数派へ。
- 多数派が無ければ、錨に競っている部分を寄せる。錨が無ければ節ごと `uncertain` にして聞き分けへ。
- 単語の中で話者が変わっていたら終わりの側の人（`TAIL_DECIDES`）。フレーム範囲は四捨五入、
  同数は音量の合計で決める。1 文字の断片は独立させない（`MIN_STANDALONE_CHARS`）。
- 節の中に同時発話の単語があれば節全体で検出し直し、同時発話なら節ごと「あずま・鉄塔」にする。
  `arbitrate.merge_split_words` は同時発話を隣に吸わせない。
- 「弱い交代は直前を保つ」規則は廃止。決められないものは印を付けて聞き分けに回す。
- 取り直し 1 回目（19:03〜19:42）を公開サイトで監査したら、閉じていない行が 12%（監査の
  しきい値 10%）に増えていた。原因は 2 つ。節がセグメント境界をまたぐので同じ人の行が
  25 秒まで伸び（前回は 20 秒超が 0 行、今回 20 行）、Worker の統合がその前の「そう、」を
  繋げずに置き去りにする。印の有無で分けた「確かに、」「そうですね。」が別行のまま残り、
  Worker が後者を相槌として落として前者が孤立する。塊の上限（10 秒・120 字）と、聞き分け後の
  繋ぎ直し（`rejoin_same_speaker`）で対処。あわせて Whisper が「ImageCast!」と空白を落とす件を、
  hotwords の綴りから空白を戻す処理（`hotwords.restore_spacing`）で塞いだ。同じ中間データで
  手元の Worker 後処理（`scripts/transcript-eval/pp_runner.ts`）まで通すと、20 秒超の生データ行
  22→0、閉じていない公開行 12%→8%、発言の閉じの却下 30→0。正解データ・切れ目は変わらず。
- 取り直し 2 回目（20:14〜21:05、上限付き版）: 公開データで話者一致 93.6% / 98.1%（C11 は 93.9 / 98.2）、
  文の途中の交代 3%（13 箇所、C11 は 19）、20 秒超の生データ行 2。**閉じていない行は 13% で監査は
  まだ 1 件。** ただし同じ中間データで旧実装を通しても 13%（新版 8%）なので、この差は Whisper の
  回ごとの句読点の付き方と、Worker の統合が上限（200 字・20 秒）に当たったとき読点で切ること
  （同じ話者が続く行の途中の切れ目が 22→45）による。次の手は Worker 側: 上限に当たったら
  直前の句点まで戻って切る（問題 3 の一部）。
- 2 回目の読み返し（`read-back.mjs`）は 8 件で、うち 5 件はミックスの Whisper が脱線した崩れた行
  （35:29〜35:46「入山口 affect 給練まあ�면参犯人」「② 그런構わけ」「wanting to choose」「by sorry」、
  56:55「Wall W … mur ready」）。外国語文字の判定がハングル・丸数字・化けた文字を見ておらず、
  語彙に無い英単語の連なりも通していた。transcriber の `looks_garbled`（ハングル等を足し、hotwords に
  無い英単語が 3 つ以上、または英単語だけで日本語が無い本文を捨てる）と、`audit-site.mjs` の同じ検査を
  足した。**今の公開データにはこの 5 行が残っている。** 消すには取り直し（3 回目）か手で直す。
  残る 3 件は校正の取りこぼし（「ぶあー障害」「悲劇か悲劇か」「あからさま祈ってる」）。

### 踏んだ罠

- faster-whisper の `compression_ratio` は 30 秒ウィンドウ単位の値。セグメント単位で捨てる
  根拠にすると、窓に 1 つ壊れた出力があるだけで普通の行が窓ごと消える。
- ミックスの Whisper は毎回別の場所で 30 秒〜3.6 分を丸ごと落とす。パラメータでは消えない。
  トラック補完が拾うので、取り直し前後の比較は「穴の秒数」で見る。
- `uv run pytest | tail -1 && restart` は tail の終了コードで通ってしまう。`set -o pipefail` を付ける。
- `audit-site.mjs` と `read-back.mjs` はリポジトリのルートから実行する。
- 正解データには「MageCast!」（正しくは Image Cast）や 2 人の区間の重なりがあり、正しい出力が
  誤りに数えられる。CER は表記差（本当／ほんと、Twitter／ツイッター）に支配され、12% 前後で動かない。
