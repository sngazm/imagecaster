## 到達点（仕組みとして入っているもの、2026-09-07 まで）

- **話者分離は節（句読点か 0.3 秒の間で区切る。Whisper のセグメント境界はまたぐ）を最小単位に決める。**
  多数派 7 割の節はその人、本人だけが鳴っている相槌は独立、決まらない節は丸ごと聞き分けへ。
  単語の中で話者が変わっていたら終わりの側の人（句読点で閉じる語は除く）、1 文字の断片は独立させない、
  同じ人の塊は 10 秒・120 字まで、聞き分けのあとに同じ人の隣り合う行を文の中で繋ぎ直す。
- **崩れた出力の判定**（`transcriber.looks_garbled`）: 外国語の文字（キリル・アラビア・ハングル・
  ベトナム・丸数字など）、hotwords に無い英単語が 3 つ以上、英単語だけで日本語が無い本文を捨てる。
  化けた文字（U+FFFD）は取り除くだけ。`audit-site.mjs` にも同じ検査がある。
- **Whisper の保険**（WSL の config.yaml、git 管理外）: `max_fallback_temperature: 0.4`、
  `prompt_reset_on_temperature: 0.1`。通常時の出力は変えずに、失敗した窓の連鎖と高い温度の
  サンプリングを塞ぐ。`condition_on_previous_text` と `temperature_fallback` も設定で切れるが、
  既定のまま（切ると本文の欠落が倍になる。下記の罠）。
- **トラック補完**で拾った行は生データに `pinned: true` の印が付く（9/7 以降の取り直しから）。
- **発言の閉じ**は、claude が本文の誤字まで直して返した答えからも末尾の印だけを取る
  （句読点を除いた一致率 0.9 以上のとき。`punctuate._salvage`）。公開ではまだ確かめていない。
- **正解エディタ**は「正解データ＝人が確かめ済みの区間だけ」。土台はいつも最新の公開データで、
  確かめ済みの区間だけ正解の本文を重ねて見せ、保存も確かめ済みの区間にかかる行だけ。
- 手元で Worker の後処理を再現できる（`scripts/transcript-eval/pp_runner.ts`。公開データと一致する）ので、
  公開前に閉じていない行の割合まで測れる。

## 残っている問題と次の手

### 3. 閉じていない行（監査に残る唯一の指摘）

内訳は 2 つ。(a) 同じ話者が続く行が Worker の統合の上限（200 字・20 秒）に当たって**読点で**切られる。
(b) 発言の閉じで claude の答えが捨てられる（4 回目は 125 行のうち 60 行。手元の実験では 0 で、
返し方のばらつきが大きい）。(b) は `_salvage` で減るはずだが公開では未確認。(a) は Worker 側で、
上限に当たったら直前の句点まで戻って切る（`mergeSegments` は「文の途中なら上限を超えても繋ぐ」
規則があり、切れるのは句読点の位置。そこを句点に限る）。旧実装の 9% は Whisper の回の当たりで、
同じ中間データなら旧 13%・新 8%。

### 1. 相槌・合いの手（残り）

- 相手の声が被った本物の相槌（本人だけが鳴っている区間が無いもの）は話し手の行に残る。
  「いいやつだ。」（藤原の短い返事）があずまの行に吸われた例が正解の新区間にある。
- 「はいはいはい、」だけの行が残る。Worker の「読点で終わる行は次の発話の一部」という規則の抜け穴。
- 候補: 相槌は書かない方針に統一（Worker の削除を強化、問いへの返事は残す）／トラック別の音量で
  相槌区間を検出して判定から除外／本文が相槌・短い返事の形なら少数派でも独立させる。
  正解データで「相槌をどう書くか」を先に決めてから。

### 4. 校正の取りこぼし

毎回 3 件ほど（「ぶあー障害」「悲劇か悲劇か」「溜めれば→詰めれば」「変や」「料理家で」）。
校正プロンプトか 2 パスの問題。校正のログに「Corrections registered: 573 for this episode」と出ており、
この回だけの置換規則が取り直しごとに積み上がっているように見える。いずれ見る。

### 補完した本文の品質（トラック vs ミックスの聞き直し）

まだ言えない。正解の範囲にかかる補完行が 2 行しか無い（トラックは正解と一致、ミックスの聞き直しは
次の話者の言葉まで拾った）。順番を「一人の区間はミックス、被りはトラック」に入れ替える案の判断材料
になるので、下の候補 1 の区間で正解を作ってから測る。測る道具は捨てた（単純なので作り直せる）。

## 踏んだ罠

- **Whisper は発言の最初の語の開始時刻を前の人の語尾まで伸ばし、最後の語の終了時刻を次の人の頭まで
  伸ばす。** 単語の頭の音量は当てにならない。旧実装のフレーム範囲の切り上げがこれを偶然打ち消して
  いたので、四捨五入に「正しく」直すだけだと悪化する。節の境界の端の語を隣に渡す規則は断片を倍に
  湧かせた（試して捨てた）。
- **Whisper の崩れは連鎖。** 前の窓を渡したまま温度 0 固定にすると失敗が連鎖して穴が 139 秒になる。
  前の窓を渡さなければ崩れないが、窓の一部を飛ばして欠落が倍になる（58→110 文字）。温度 0 の復号は
  決定的で、回ごとの差はすべて fallback の経路から来る。large-v3 は turbo より 3 倍遅くて悪い。
- ミックスの Whisper が落とす量は回ごとに 11〜169 秒とばらつく。取り直し前後の比較は同じ中間データで
  やる。公開データ同士の CER の差は Whisper の回の差に埋もれる。
- faster-whisper の `compression_ratio` は 30 秒ウィンドウ単位の値。セグメント単位で捨てる根拠にすると
  普通の行が窓ごと消える。
- 「音量が小さい交代は直前の話者を保つ」は小声の話者の短い問いを奪う。決められないものは印を付けて
  聞き分けに回す。「捨てたセグメントの隣で英単語が 1 つでもあれば捨てる」は Claude Code や Discord
  まで落とす（hotwords に無い英語が普通に出る）。
- 節が Whisper のセグメント境界をまたぐと同じ人の行が 25 秒まで伸び、Worker の統合（20 秒まで）が
  その前の短い行を置き去りにする。塊の上限は Worker の上限より短くする。
- 正解データには表記差（本当／ほんと、Twitter／ツイッター）があり、CER は 9〜12% で動かない。
  正解の時刻の側が疑わしい箇所もある（1369 秒）。
- `uv run pytest | tail -1 && restart` は tail の終了コードで通る。`set -o pipefail` を付ける。
  `uv` は非対話の ssh では PATH に無い。ssh 越しの awk に `$0` を書くと手前のシェルに食われる。
- `audit-site.mjs` と `read-back.mjs` はリポジトリのルートから実行する。`read-back` はローカルの
  claude のログインが切れると落ちる（`Not logged in`）。
- 管理画面は `pnpm deploy:admin` では配られない（admin に deploy スクリプトが無い）。push を Pages が拾う。
